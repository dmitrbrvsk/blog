# ADR 0001: Аудит в той же БД, что и продукты

## Статус

Accepted (MVP)

## Контекст

Нужна гарантия «изменение параметров продукта всегда сопровождается записью кто/что/когда». Варианты:

1. Таблица `audit_events` в той же PostgreSQL, запись в одной транзакции.
2. Отльный Audit Service + синхронный вызов.
3. Запись в Kafka / event log как primary audit.

## Решение

Вариант 1: **append-only таблица в той же БД**, insert в той же транзакции, что UPDATE продукта.

## Последствия

(+) Атомарность без 2PC.  
(+) Простые запросы журнала по продукту.  
(+) Соответствует объёму MVP.  
(−) Audit делит ресурсы с OLTP — при текущих объёмах приемлемо.  
(−) Для SIEM/DWH позже добавим outbox → Kafka, не меняя UX аудита.
