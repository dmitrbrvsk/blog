# ADR 0002: Идентичность актора через IdP `sub`

## Статус

Accepted (MVP)

## Контекст

В журнале должно быть однозначно видно, кто изменил параметры. Логин/ФИО могут меняться (переименование УЗ, смена email).

## Решение

- Обязательный `actor_id` = OIDC claim `sub` (стабильный идентификатор УЗ).
- Обязательный `actor_login` на момент события (денормализация для читаемости).
- Опциональный `actor_display_name`.
- UI показывает login/name; расследования и API-фильтры опираются на `actor_id`.
- Каждое пользовательское изменение получает `action_id` (UUID), возвращаемый в ответе PATCH.

## Последствия

(+) Стабильная корреляция с IdP и HR/IAM.  
(+) Читаемый журнал без join на момент просмотра.  
(−) При смене login исторические строки сохраняют старый login — это желаемо (as-of факт).
