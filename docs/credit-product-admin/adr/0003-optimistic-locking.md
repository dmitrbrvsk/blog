# ADR 0003: Optimistic locking через `version`

## Статус

Accepted (MVP)

## Контекст

Два оператора могут одновременно открыть карточку продукта и сохранить разные правки. Нужна предсказуемая модель конфликтов без тяжёлых distributed lock.

## Решение

- Поле `version INT` на `credit_products`.
- Клиент присылает `version` в PATCH.
- Сервер делает `SELECT … FOR UPDATE`, сравнивает версию; при расхождении — `409 Conflict`.
- Успешный UPDATE делает `version = version + 1`.

## Последствия

(+) Простая семантика, хорошо ложится на REST.  
(+) UI может предложить refetch + merge вручную.  
(−) Нет авто-merge полей — для редких админских правок достаточно.  
(−) Pessimistic lock на всю сессию редактирования не делаем (плохо для UX).
